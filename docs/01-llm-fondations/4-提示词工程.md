# 2.4 Prompt Engineering

## 1. 核心定义

Prompt Engineering 不是“写一句更厉害的话”，而是：

> 用结构化、可维护、可测试的方式，引导模型在特定任务中产生更稳定的行为。

一个实际 Prompt 往往由多部分组成：

```text
System Instructions
↓
Task Instructions
↓
Few-shot Examples
↓
Runtime Context
↓
User Input
↓
LLM
```

---

## 2. System Prompt

System Prompt 用于定义模型在应用中的：

- 职责
- 任务目标
- 行为规则
- 输出要求
- 限制条件

可以简单理解为：

```text
System Prompt
= Application-level Instructions

User Prompt
= Current Task / Input
```

在 Agent 中，System Prompt 还可能包含：

```text
Tool Usage Rules
Decision Rules
Stop Rules
Escalation Rules
```

但需要注意：

```text
Prompt ≠ Permission System
Prompt ≠ Hard Guardrail
```

高风险行为不能只依赖 Prompt 控制。

---

## 3. Role Prompt

Role Prompt 用于指定模型执行任务时的职责或视角。

例如：

```text
You are a senior backend engineer.
```

它可以帮助模型聚焦于相关维度，例如：

```text
Scalability
Security
Maintainability
Error Handling
```

核心原则：

> Role Prompt 用于明确职责和视角，而不是提升模型能力上限。

---

## 4. Few-shot Prompt

Few-shot Prompt 是提供少量：

```text
Input → Expected Output
```

示例，让模型理解任务模式。

例如：

```text
Input:
I forgot my password.

Output:
account_support

Input:
Where is my package?

Output:
shipping
```

Few-shot 特别适合：

```text
Classification
Information Extraction
Formatting
Style Control
Edge Cases
```

推荐优先选择：

```text
Normal Case
Important Edge Case
Easy-to-confuse Case
```

Few-shot 不是越多越好，过多示例会增加：

```text
Token Cost
Context Noise
Prompt Conflict
```

---

## 5. Chain-of-Thought 基本认识

Chain-of-Thought（CoT）可以理解为：

> 模型解决复杂问题时进行多步骤推理的过程。

简化表示：

```text
Problem
↓
Intermediate Reasoning
↓
Decision
↓
Answer
```

工程上更应该关注：

```text
Final Decision
Supporting Evidence
Short Rationale
Validation Result
```

而不是依赖展示完整的内部推理过程。

### CoT vs Agent Loop

```text
Chain-of-Thought
= Model-level reasoning

Agent Loop
= System-level interaction
```

Agent Loop 会与 Tool、Environment 多轮交互，而 CoT 主要属于模型的问题求解过程。

---

## 6. Prompt Template

Prompt Template 是带动态变量的可复用 Prompt 结构。

例如：

```text
Role:
{role}

Task:
{task}

Context:
{context}

User Input:
{user_input}

Output:
{output_format}
```

它通常组合：

```text
Static Instructions
+
Dynamic Context
+
User Input
+
Examples
+
Output Requirements
```

Prompt Template 的主要价值：

```text
Reusable
Maintainable
Consistent
Testable
```

需要避免：

```text
字符串随意拼接
Context 无限增长
Instructions 与不可信数据混在一起
```

---

## 7. Prompt Versioning

Prompt 修改会直接改变模型行为：

```text
Prompt Change
≈
Behavior Change
```

因此 Prompt 应该像代码一样进行版本管理。

至少记录：

```text
Prompt Name
Version
Changes
Eval Result
```

例如：

```text
research-agent

v1.2

Changes:
- clarify search conditions
- add citation rules

Eval:
82% → 89%
```

学习阶段直接使用 Git 管理 Prompt 即可。

---

## 8. Prompt Versioning 与 Eval

Prompt 修改后不应该只凭几个案例判断效果。

推荐流程：

```text
Prompt Change
↓
Eval Dataset
↓
Compare Results
↓
Deploy / Rollback
```

核心原则：

> Prompt Engineering without Evaluation 很容易变成 Prompt Guessing。

---

## 9. Prompt Engineering 的边界

不同机制承担不同职责：

```text
Prompt
= Behavior Guidance

Schema
= Output Contract

Code
= Deterministic Logic

Guardrails
= System Constraints

Eval
= Behavior Measurement
```

不要用 Prompt 代替：

```text
权限控制
强业务规则
Schema Validation
安全边界
确定性程序逻辑
```

---

## 10. 常见错误

### 过度依赖 Role Prompt

```text
You are the world's best engineer...
```

不会凭空提升模型能力。

### Prompt 无限加长

不断追加规则和示例可能造成：

```text
Cost ↑
Latency ↑
Conflict ↑
Context Noise ↑
```

### 用 Prompt 代替代码

强业务规则应该由程序和 Guardrails 保证，而不是只写在 Prompt 中。

### Prompt 修改不做 Eval

单个 Case 变好，不代表整体效果提升。

---

## 11. 核心心智模型

```text
System Prompt
↓
Role / Rules / Objective
↓
Few-shot Examples
↓
Prompt Template
↓
Runtime Variables
↓
LLM
↓
Eval
↓
Prompt Version Update
```

Prompt Engineering 的工程目标不是“写更华丽的 Prompt”，而是：

> 让 Prompt 可设计、可复用、可测试、可比较、可回滚。

---

## 12. Interview Questions & Answers

### 1. System Prompt 和 User Prompt 有什么区别？

```text
System Prompt = 定义应用级职责、规则和行为
User Prompt   = 提供当前任务或输入
```

### 2. Few-shot Prompt 有什么作用？

Few-shot 通过少量输入输出示例，让模型更准确地理解任务模式、分类边界和输出方式。

### 3. Chain-of-Thought 和 Agent Loop 有什么区别？

```text
CoT = 模型的问题求解过程
Agent Loop = 模型与 Tool / Environment 的多轮交互过程
```

### 4. 为什么需要 Prompt Versioning？

因为 Prompt 修改会改变模型行为，需要记录版本、比较效果，并在效果下降时支持回滚。

### 5. 为什么 Prompt Engineering 必须配合 Evaluation？

因为少数案例变好不代表整体效果提升。Prompt 修改后需要通过 Eval 判断是否真正改善系统表现。

---

## 13. 核心速记

```text
System Prompt
= Application-level Instructions

Few-shot
= Teach by Examples

Role Prompt
= Define Perspective

Prompt Change
= Behavior Change

Prompt Engineering + Eval
> Prompt Guessing
```
