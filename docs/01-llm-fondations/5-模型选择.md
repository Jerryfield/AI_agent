# 2.5 Model Selection

## 1. 核心定义

Model Selection 不是简单选择“最强模型”，而是根据任务需求，在多个维度之间做 Trade-off：

```text
Capability
Context Length
Reasoning Ability
Latency
Cost
```

核心目标：

> 为当前任务选择“足够可靠、成本合理、延迟可接受”的模型。

---

## 2. Model Capability

不同模型适合的任务不同，例如：

```text
Text Generation
Classification
Information Extraction
Coding
Tool Calling
Reasoning
Multimodal
Long-context Processing
```

模型能力不是单一排名，而是多维度能力组合。

因此：

```text
Simple Classification
→ Fast / Cheap Model

Complex Coding / Planning
→ Strong Reasoning Model
```

核心原则：

> Task-Model Matching 比“永远使用最强模型”更重要。

---

## 3. Context Length

Context Length 表示一次调用中模型能够处理的最大 Token 范围。

Context 可能包括：

```text
System Prompt
User Input
Conversation History
Retrieved Documents
Tool Results
Code
Memory
Output Tokens
```

Context Window 越大，并不代表应该放入更多内容。

过长 Context 可能导致：

```text
Cost ↑
Latency ↑
Noise ↑
Important Information 被淹没
```

因此：

> Large Context Window ≠ Use More Context.

更合理的做法是只提供当前任务真正需要的信息。

---

## 4. Reasoning Ability

Reasoning Ability 主要影响模型处理以下任务的能力：

```text
Multi-step Problem Solving
Complex Constraints
Planning
Logical Analysis
Complex Coding
Tool Selection
```

简单任务通常不需要强 Reasoning Model。

例如：

```text
信息提取
分类
格式转换
```

使用复杂推理模型可能只会增加：

```text
Latency
Cost
```

而 Quality 提升有限。

因此：

> Reasoning 是一种按需使用的资源。

---

## 5. Latency

Latency 表示模型完成请求所需时间。

不同任务对延迟的敏感程度不同：

```text
Interactive Task
→ 更关注 Latency

Offline / Batch Task
→ 可以更关注 Quality / Cost
```

例如：

```text
聊天 / 搜索 / 实时助手
→ 更重视快速响应

代码审查 / 批量分析
→ 可以接受更长延迟
```

模型选择需要根据具体使用场景平衡 Quality 和 Latency。

---

## 6. Cost

模型成本通常受到：

```text
Model Price
Input Tokens
Output Tokens
Number of Calls
```

影响。

对于 Agent，还要考虑：

```text
Agent Loop
Retry
Tool Results
Reflection
Evaluation
```

因此不能只看：

```text
Cost per API Call
```

而应该关注：

```text
Cost per Successful Task
```

便宜模型如果导致更多 Retry、错误 Tool Call 或失败循环，最终总成本可能反而更高。

---

## 7. Model Selection 的核心 Trade-off

模型选择通常需要同时权衡：

```text
Quality
Cost
Latency
Reliability
```

不存在一个模型可以同时做到：

```text
最强
最快
最便宜
```

因此 Model Selection 本质上是：

> 一个工程优化问题。

---

## 8. Model Routing

Model Routing 是根据任务类型、复杂度或运行状态，动态选择不同模型。

传统方式：

```text
All Requests
↓
One Model
```

Model Routing：

```text
Request
↓
Router
├── Simple Task  → Fast Model
├── Complex Task → Reasoning Model
├── Coding Task  → Coding Model
└── Vision Task  → Multimodal Model
```

它的主要价值：

```text
Reduce Cost
Reduce Latency
Improve Resource Utilization
```

---

## 9. 常见 Routing Strategy

### 按任务类型

```text
Classification
→ Small Model

Coding
→ Coding-capable Model

Complex Reasoning
→ Reasoning Model
```

### 按任务复杂度

```text
Simple
→ Cheap Model

Complex
→ Strong Model
```

### 按 Context Size

```text
Short Context
→ General Model

Very Long Context
→ Long-context Model
```

### 按失败结果升级

```text
Fast Model
↓
Success?
├── Yes → Return
└── No  → Strong Model
```

这种方式也叫：

```text
Model Escalation
```

---

## 10. Router 的实现方式

### Rule-based Router

通过代码规则选择模型：

```python
if task.type == "classification":
    use_small_model()
elif task.type == "complex_reasoning":
    use_reasoning_model()
```

优点：

```text
Simple
Deterministic
Cheap
```

### Model-based Router

使用一个模型判断任务类型或复杂度：

```text
Request
↓
Router Model
↓
Task Type
↓
Target Model
```

更加灵活，但会增加：

```text
Cost
Latency
Routing Error
```

因此：

> 能用简单规则可靠解决，就不要优先引入复杂 Router。

---

## 11. Model Routing 的风险

Routing 会增加：

```text
Architecture Complexity
Debugging Complexity
Evaluation Complexity
Routing Errors
```

因此 Router 本身也需要 Evaluation。

常见指标：

```text
Routing Accuracy
Task Success Rate
Latency
Cost
Fallback Rate
```

---

## 12. Model Selection 应该由 Eval 驱动

不要只凭主观感觉判断模型。

推荐流程：

```text
Eval Dataset
↓
Model A / B / C
↓
Compare
↓
Task Success
Quality
Latency
Cost
Failure Rate
↓
Select Model
```

核心原则：

```text
Prompt Change → Eval
Model Change  → Eval
```

---

## 13. 实用选择框架

选择模型前可以依次判断：

```text
1. 任务有多复杂？
2. 是否需要强 Reasoning？
3. Context 有多长？
4. 用户是否对 Latency 敏感？
5. Cost Budget 是多少？
6. 是否需要 Tool Calling / Structured Output？
7. 是否值得引入 Model Routing？
```

最终流程：

```text
Task
↓
Requirements
↓
Candidate Models
↓
Eval
↓
Select / Route
```

---

## 14. 核心工程原则

避免两个极端：

### 永远使用最强模型

可能导致：

```text
Cost ↑
Latency ↑
```

但 Quality 提升有限。

### 永远使用最便宜模型

可能导致：

```text
Retry ↑
Tool Error ↑
Agent Loop ↑
Task Failure ↑
```

真正的目标是：

> 选择完成当前任务所需的最小充分模型。

---

## 15. Interview Questions & Answers

### 1. Model Selection 最重要的考虑因素有哪些？

主要包括 Capability、Context Length、Reasoning Ability、Latency 和 Cost，生产环境还应结合 Reliability 与实际 Eval 结果。

### 2. 为什么 Context Window 越大不代表越好？

因为更长 Context 会增加 Cost、Latency 和 Noise，能够容纳更多信息不代表应该使用更多信息。

### 3. 为什么不能所有任务都使用最强 Reasoning Model？

因为简单任务通常不需要复杂推理，使用更强模型会增加 Cost 和 Latency，却不一定明显提升效果。

### 4. 什么是 Model Routing？

Model Routing 是根据任务类型、复杂度、Context 或运行结果，动态选择不同模型的机制。

```text
Simple Task → Fast Model
Complex Task → Reasoning Model
```

### 5. Model Selection 为什么需要 Evaluation？

因为模型效果不能只靠主观判断，需要在真实任务上比较 Task Success、Quality、Latency、Cost 和 Failure Rate。

---

## 16. 核心速记

```text
Best Model
≠
Strongest Model

Large Context
≠
Use More Context

Reasoning
= On-demand Resource

Cost per API Call
≠
Cost per Successful Task

Model Routing
= Match Model to Workload

Model Selection
= Eval-driven Trade-off
```
