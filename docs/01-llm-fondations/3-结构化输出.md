# 2.3 Structured Output

## 1. 核心定义

Structured Output 是让 LLM 按预定义结构返回结果，而不是自由文本。

例如：

```json
{
  "intent": "weather_query",
  "city": "Tokyo",
  "date": "tomorrow"
}
```

相比自然语言文本，结构化结果更适合程序直接解析、校验和处理。

---

## 2. JSON Output

JSON Output 只是要求模型以 JSON 形式返回结果。

例如：

```json
{
  "name": "Jerry",
  "age": 25
}
```

但“合法 JSON”不代表“结构一定正确”。

可能出现：

```json
{
  "name": "Jerry",
  "age": "25"
}
```

虽然 JSON 语法合法，但 `age` 类型不符合预期。

因此：

```text
JSON Syntax Correct
≠
Schema Correct
≠
Semantic Correct
```

---

## 3. JSON Schema

JSON Schema 用来定义 JSON 应该具备的结构和约束，例如：

- 有哪些字段
- 字段类型
- 必填字段
- 枚举值
- 数值范围
- 字符串格式

示例：

```json
{
  "type": "object",
  "properties": {
    "name": {
      "type": "string"
    },
    "age": {
      "type": "integer"
    }
  },
  "required": ["name", "age"]
}
```

可以简单理解为：

```text
JSON
= 数据

JSON Schema
= 数据结构规范
```

---

## 4. Schema Validation

Validation 用于检查模型输出是否符合 Schema。

```text
LLM Output
↓
Schema Validation
↓
Valid?
├── Yes → Application Logic
└── No  → Retry / Repair / Reject
```

常见验证内容：

```text
Required Fields
Type
Enum
Minimum / Maximum
Pattern
Format
```

需要区分三层：

```text
Syntax Validation
↓
JSON 能否解析

Schema Validation
↓
结构和类型是否正确

Semantic Validation
↓
内容本身是否合理
```

Schema Validation 不能保证模型答案本身一定正确。

---

## 5. Pydantic

Pydantic 是 Python 中常用的数据建模和 Validation 工具。

示例：

```python
from pydantic import BaseModel

class UserInfo(BaseModel):
    name: str
    age: int
```

在 LLM Application 中可以形成：

```text
Pydantic Model
↓
JSON Schema
↓
Structured Output
↓
Pydantic Validation
↓
Typed Python Object
```

相比手写 JSON Schema，Pydantic 更适合 Python 工程代码维护。

---

## 6. Pydantic 在 Agent 中的典型用法

例如定义 Agent 决策：

```python
from typing import Literal
from pydantic import BaseModel

class TaskDecision(BaseModel):
    action: Literal["search", "calculate", "answer"]
    query: str | None = None
    confidence: float
```

合法输出：

```json
{
  "action": "search",
  "query": "Tokyo weather",
  "confidence": 0.94
}
```

非法输出：

```json
{
  "action": "delete_database",
  "query": null,
  "confidence": 0.9
}
```

因为：

```text
action ∉ ["search", "calculate", "answer"]
```

Validation 会失败。

---

## 7. Structured Response

Structured Response 是模型 API 根据预定义 Schema 返回程序可直接消费的结构化结果。

对比：

```text
Free-form Response
→ 面向人类阅读

Structured Response
→ 面向程序处理
```

程序可以直接根据字段执行逻辑：

```python
if response.action == "search":
    search(response.query)
```

---

## 8. Structured Output 与 Tool Calling

两者都依赖结构化模型输出，但用途不同：

```text
Structured Output
= 描述数据

Tool Call
= 描述 Action
```

例如普通 Structured Output：

```json
{
  "category": "refund",
  "confidence": 0.95
}
```

Tool Call：

```json
{
  "tool": "get_weather",
  "arguments": {
    "city": "Tokyo"
  }
}
```

可以把 Tool Call 看作一种特殊的 Structured Output。

---

## 9. Prompt、Schema、Validation 的区别

```text
Prompt
= 告诉模型应该怎么输出

Schema
= 定义结果应该长什么样

Validation
= 检查结果实际上是否符合要求
```

因此：

```text
Prompt ≠ Hard Constraint
```

只在 Prompt 中要求“必须输出 JSON”，并不能代替 Schema Validation。

---

## 10. Structured Output 的边界

Structured Output 可以提高：

```text
格式可靠性
结构可靠性
类型可靠性
```

但不能保证：

```text
事实正确
推理正确
语义正确
业务决策正确
```

例如：

```json
{
  "answer": "Paris",
  "confidence": 0.99
}
```

结构完全合法，但内容仍可能是错的。

因此：

```text
Structured Output
≠
Correct Answer
```

---

## 11. 核心心智模型

```text
Free-form Text
↓
JSON
↓
JSON Schema
↓
Schema Validation
↓
Pydantic / Typed Object
↓
Application Logic
```

能力逐层增强：

```text
JSON
= 可解析

Schema
= 可定义

Validation
= 可检查

Pydantic
= 可类型化

Structured Response
= 可直接进入程序逻辑
```

## 12. Interview Questions & Answers

### 1. 什么是 Structured Output？

Structured Output 是让 LLM 按预定义的数据结构返回结果，使程序可以稳定解析和处理。

### 2. JSON Output 和 JSON Schema 有什么区别？

```text
JSON Output = 数据使用 JSON 格式
JSON Schema = 定义 JSON 的字段、类型和约束
```

### 3. 为什么只要求模型输出 JSON 还不够？

因为 JSON 语法可能合法，但字段名、类型、必填项或结构仍可能不符合程序要求。

### 4. 什么是 Schema Validation？

Schema Validation 用于检查模型输出是否满足预定义的字段、类型和约束要求。

### 5. Schema Validation 能保证模型答案正确吗？

不能。它只能保证结构符合要求，不能保证事实、推理或业务语义正确。

### 6. Pydantic 在 LLM Application 中有什么作用？

Pydantic 用 Python 类型定义数据结构，并负责 Schema 生成、数据解析和 Validation。

### 7. Structured Output 和 Tool Calling 有什么关系？

Tool Call 可以看作特殊的 Structured Output：

```text
Structured Output = 描述数据
Tool Call = 描述 Action
```

### 8. Prompt、Schema 和 Validation 有什么区别？

```text
Prompt = 告诉模型怎么做
Schema = 定义结果结构
Validation = 检查结果是否符合要求
```

### 9. 为什么 Agent 特别依赖 Structured Output？

因为 Agent 的模型输出经常需要直接进入程序逻辑或影响下一步 Action，必须做到可解析、可校验。

### 10. Structured Output 能解决 Hallucination 吗？

不能。它主要解决格式和结构可靠性，不能保证模型生成内容本身正确。

---

## 13. 核心速记

```text
JSON ≠ Schema

Schema ≠ Validation

Prompt ≠ Hard Constraint

Structured Output ≠ Correct Answer

Tool Call
= Special Structured Output
```
